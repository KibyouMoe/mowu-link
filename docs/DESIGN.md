## 0. 一页定位

**一句话**：一只在你桌面上**自己上班**的搭子。你给它方向，它自己干活，晚上给你一份日报。

**它是什么**
- 一个**自治循环**：它有自己的计划表，会自己决定去采集、做东西、摆摊、休息、睡觉。你不点，它也在动。
- 一个**产出系统**：它干出来的东西会累积——素材、成品、摆到桌面上的物件、每天一篇日报。你能看见"这几天系统跑了什么"。
- 一个**同一角色**：电脑上是活的，手机上是它本人（同一份存档、同一个服务器），不是两份数据。
- 一个**能说话的壳**：AI 只负责台词和日报旁白。关掉 AI，它照样运转。

**它不是什么**
- **不是 QQ 宠物复刻**。不复刻美术、不复刻数值、不复刻 400 级、不复刻死亡与疾病。
- **不是需要你照顾的婴儿**。它不会饿死、不会生病、不会因为你三天没开电脑而受苦。
- **不是番茄钟 / 待办工具**。它不提醒你工作，不评价你的效率。
- **不是 AI 聊天壳**。聊天是它的一个器官，不是它的全部。
- **不是手游**。无内购、无每日任务、无体力、无签到、无排行榜。

**它凭什么成立**（三条不可妥协）
1. **自治优先**：核心乐趣是"看一个系统自己运转并产出"，不是"点按钮喂数值"。
2. **零惩罚**：任何数值见底都只降低效率，不产生负面事件。缺席不该被罚。
3. **可缺席**：一天看一次足够，三天不看也不损失。回来看到的是收获，不是尸检报告。

**什么算成功**
- 装好第 3 天，我还会主动点开日报看它昨天干了什么。
- 它会做出我没让它做、但事后觉得合理的事（比如素材攒够了自己去做那张图纸）。
- 关掉电脑一晚，第二天打开，它说"我睡了 8 小时，早上采了两趟木头"。

### 1.1 数值系统

原版只有 **8 个数字**：

| 字段 | 含义 | 上限 | 衰减 | 备注 |
|---|---|---|---|---|
| `hunger` | 饱食 | `3000 + 100×min(level,30)` = 1 级 3100 | −rand(5,8)/分钟 | 心情 <600 时额外 −2 |
| `clean` | 清洁 | 同上 | −rand(5,8)/分钟 | 同上 |
| `mood` | 心情 | 1000 | −rand(2,4)/分钟 | 打工/上学时更快 |
| `health` | 健康 | 5 | 由疲劳掷骰 | 5 正常 → 4..1 生病 → 0 死亡 |
| `growth` | 成长值 | 无上限 | **+260/小时**（只算在线分钟） | 唯一的"进度" |
| `yb` | 元宝 | 无 | 打工/任务 | 唯一货币 |
| `intel` `charm` `strong` | 智力/魅力/武力 | 无 | 学习/道具 | 打工门槛 |

**关键公式**（`GrowUp.js`，逐字转写）：

```js
// 成长：基础 260/小时，按心情/健康/饥饿/清洁扣减
getEffectGrowthRate() {
  260
  - mood惩罚   // 900+:0, 700:20, 500:70, 300:100, 100:140, 0:180
  - health惩罚 // 5:0, 4:30, 3:80, 2:120, 1:160
  - (hunger < 720 ? 80 : 0)
  - (clean  < 1080 ? 80 : 0)   // 与饥饿共用一个槽，不叠加
  + 粉钻10×等级 + 情侣10
}

// 衰减：每 60 秒
hunger -= rand(5,8) + (mood<600 ? 2 : 0) + 活动附加
clean  -= rand(5,8) + (mood<600 ? 2 : 0) + 活动附加
mood   -= rand(2,4) + 活动附加
```

**换算成人话**：

| 指标 | 数值 | 后果 |
|---|---|---|
| 饱食续航 | 3100 ÷ 6.5/分钟 | **7.9 小时见底**，6.1 小时到饥饿线 |
| 到 Lv10 | 8,000 成长 ÷ 260/h | 30.8 小时 |
| 到 Lv16（成年） | 32,500 | 125 小时（5 天连续在线） |
| 到 Lv100 | 8,218,600 | **31,610 小时 = 3.6 年** |
| 到 Lv400 | 539,395,200 | **237 年**（表里真有 400 级） |
| 一顿饱饭 | 3100 × 0.05 元宝/点 | 155 元宝 |
| 搬砖 30 分钟 | 10 元宝 | **只够 1/15.5 顿饭** |

### 1.2 状态机

原版是**两层**，这个分层值得照抄：

```
逻辑层（存档）  petInfo{8 个数字}
                activeOption{work | study | trip | ill | die}   ← 互斥的"大事"
                saveJsonData.activity  ← 当前任务已用分钟（落盘，重启续算）
动画层（运行时）Machine.pose ∈ {enter, normal, walk, look, play, speak, eat, clean,
                toy, liedown, lying, getup, hideleft, hideright, drag, work, study,
                trip, sick, dying, die, revival, bury, levUp, ...}
```

原版代码里有一句注释，直接把设计意图写出来了：

> *"Visual poses can be replaced before they run... Accounting must not depend on an animation's exit callback."*

**数值推进走独立 60 秒定时器，动画只是表现。** 这条必须照抄——否则手机端切后台、窗口最小化、动画被抢占，都会让结算丢帧。

动画序列器（`machine.ts`）规则：
- 12 fps 轮询，按帧数判断播完
- `play()` 抢占并清队列；`add()` 追加
- 单帧动画（Stand/Die）与 `normal/hide/drag/walk` 视为 hold，不会自己结束
- 健康 = 1 时，除白名单（cure/die/revival/hide/appear/enter）外一律强制 `dying`

### 1.3 交互与反馈

| 交互 | 原版做法 | 反馈 |
|---|---|---|

| 点身体 | `face.ts`：10 个命中点 × 3 阶段 × 4 心情 | 对应部位动画 + 气泡 + mood +5~15 |
| 右键 | PopupMenu，坐标设为鼠标屏幕坐标 | 喂食/洗澡/玩耍/看病/资料/设置/隐藏 |
| 走到边缘 | 距边 < 36 px | 探头（半个身子出屏） |
| 待机 | 20–60 秒随机 | 10% 躺下 / 1/3 走动 / 2/3 玩耍 / 30% 说日期台词 |
| 全屏应用 | 前台窗口全屏检测 | 自动隐藏，退出后回来 |
| 托盘 | 9 种状态图标 | 不打扰但可见（死>暂停>病>打工>上学>旅游>脏>饿>正常） |
| 气泡 | 文本 + 1 个按钮 + 可选动作 | 点按钮触发回调（"带你看病"） |
| 离线 | `resumeTask()` 用时间差补分钟 | "我回来了" + 产出结算 |

### 1.4 为什么它上瘾（2006 年的答案）

1. **即时因果**：数值在你眼前掉，你喂它立刻涨。反馈回路 2 秒闭环。
2. **稀缺收集**：560 种食物、288 种清洁用品、图鉴、纪念品、背景。
3. **掉落老虎机**：打工/上学完成时掉 1–2 件随机物品（75%/25%），43% 日用品 / 43% 食物 / 14% 药品。**真正的奖励是掉落，不是工资**（工资只有饭钱的 1/15）。
4. **情感绑定**：它撒娇、抱怨、生病了喊你。台词是拟人的，不是系统的。
5. **异步惊喜**：旅游一小时回来，带回明信片和"奇遇"。
6. **社交炫耀**：粉钻、等级、宠物王、串门。
7. **沉没成本**：400 级，等级即身份。

### 1.5 哪些是二十年前的时代包袱

| 包袱 | 证据 | 为什么不能留 |
|---|---|---|
| **强制在线时长** | 成长 260/h 只按在线分钟累加，关掉不涨 | 逼玩家 24 小时挂机；这是"在线时长"KPI，不是陪伴 |
| **高频打卡** | 饱食 7.9 小时见底，一天要看 3–4 次 | 把陪伴变成值班 |
| **惩罚链** | 饿 → 病（3 条链 × 4 级）→ 死 → 还魂丹 | 用恐惧驱动留存；缺席即受罚 |
| **无限等级 treadmill** | 400 级，L100 = 3.6 年，L400 = 237 年 | 数值设计放弃治疗，靠时间堆 |
| **经济失衡** | 打工 = 饭钱的 1/15.5 | 打工不是谋生，是抽奖入口（逼你去刷掉落） |
| **付费墙** | 粉钻加速成长、限时道具 | 单机项目不需要，也不该有 |
| **挂机竞赛** | 2026 现代版：高玩每天学 19 小时、冒险 600 次 | 二十年后变本加厉；社区为此写了 117★ 的外挂 |

**最有力的一条证据**：复刻社区自己也在偷偷改。`DQGX5BP/qqpet` 把衰减从 `rand(5,8)` 改成 `rand(2,3)`（原版的 40%），续航从 7.9 小时拉到 20.7 小时——但成长率也从 260/h 降到 80/h，结果 L100 从 3.6 年变成 **11.7 年**。

**照抄数值表 + 局部修补 = 比原版更肝。** 这就是为什么我们不复刻，只借结构。

## 2. 我们的设计

### 2.1 核心循环

```
        ┌─────────────────────────────────────────────┐
        │  玩家：定偏好（攒素材 / 做成品 / 赚钱）      │
        │        偶尔指派一次、买图纸、布置桌面        │
        └───────────────────┬─────────────────────────┘
                            │ 只改权重，不逐步操作
                            ▼
   ┌────────────── 服务器（权威，60 秒 tick）──────────────┐
   │  计划器：按优先级挑下一个活动                          │
   │    ↓                                                  │
   │  活动执行（25–120 分钟，落盘，离线按时间戳补算）        │
   │    ↓                                                  │
   │  结算：产出 → 库存 / 技能 +0.6~1.2 / 数值变化          │
   │    ↓                                                  │
   │  事件流 → 日报（模板 or LLM 旁白）                     │
   └───────────────┬──────────────────────┬────────────────┘
                   │ WS 广播               │
                   ▼                      ▼
            桌面端（Godot）          手机端（PWA）
            它在动、在干活、在睡      看状态、看日报、聊天
```

**一句话**：玩家定策略，宠物执行，系统产出，日报汇报。

### 2.2 数值表

时间单位：分钟。服务器每 60 秒结算一次（省电，与原版一致）。

| 键 | 名称 | 范围 | 初值 | 变化率 | 作用 | 见底会怎样 |
|---|---|---|---|---|---|---|
| `energy` | 精力 | 0–100 | 100 | 工作 −8/h；休息 +12/h；睡眠 +20/h | 开工门槛 + 效率乘子 | 自动去休息，**不受伤** |
| `satiety` | 饱食 | 0–100 | 80 | 清醒 −1.2/h；睡眠 −0.4/h | 精力恢复乘子 | 效率 ×0.6，**不饿死** |
| `mood` | 心情 | 0–100 | 70 | 工作 −1.5/h；休息 +3/h；玩耍 +10/次；布置 +5/次 | 品质档 ±1 | 品质降档，**不离家出走** |
| `tidy` | 整洁 | 0–100 | 90 | −0.8/h | 心情自然回升的开关 | 心情不再自然涨，**不生病** |

**续航自检**（写死在文档里，防止以后偷偷调快）：

| 场景 | 计算 | 结果 |
|---|---|---|
| 饱食 80 → 0 | 80 ÷ 1.2 | **66.7 小时（2.8 天）** |
| 整洁 90 → 0 | 90 ÷ 0.8 | **112 小时（4.7 天）** |
| 心情 70 → 0（持续工作） | 70 ÷ 1.5 | 46.7 小时 |
| 精力 100 → 0（持续工作） | 100 ÷ 8 | 12.5 小时 |

结论：**一天看一次绰绰有余，三天不看也不会崩**。这是"零惩罚"的量化定义。

**效率公式**

```
energy_mult  = energy ≥ 50 ? 1.0 : energy ≥ 20 ? 0.8 : 0.5
satiety_mult = 0.6 + 0.4 × satiety / 100
eff = energy_mult × satiety_mult
```

满状态 = 1.0，最差 = 0.5 × 0.6 = 0.30。**永远不为 0**——它总会干点什么，只是慢。

**品质档**

```
skill_tier = floor(skill / 34)                  // 0 / 1 / 2
mood_bonus = mood ≥ 80 ? +1 : mood < 30 ? −1 : 0
tier = clamp(skill_tier + mood_bonus, 0, 3)     // 粗糙 / 普通 / 精良 / 精品
售价 = 基础价 × (1 + 0.6 × tier)
```

**技能（唯一的成长线）**

| 技能 | 作用 | 升级 | 到 100 所需次数 | 专精（二选一） |
|---|---|---|---|---|
| 采集 `gathering` | 采集数量 + 稀有率 | +0.6~1.2/次 | ≈ 100 次采集 | 矿工（矿 +50%/木 −30%）或 林人（反之） |
| 制作 `crafting` | 品质档上限 | +1.0/次 | ≈ 80 次制作 | 匠人（25% 概率 +1 档）或 量产（出 2 件，−1 档） |
| 交涉 `trading` | 售价 | +0.8/次 | ≈ 120 次摆摊 | 商人（售价 +30%）或 人脉（订单 +1） |

**没有等级、没有经验条、没有 400 级。** 三条技能全满 + 专精 ≈ 300 次活动 ≈ 200 游戏小时，是"有尽头"的成长。到顶之后它继续干活，只是不再变强——这个项目不靠无限成长留人。

### 2.3 状态机

```
                    ┌──────────┐
        ┌──────────▶│   IDLE   │◀─────────── 一切结束
        │           └────┬─────┘
        │                │ 计划器每 5 分钟评估
        │   ┌────────────┼────────────┬──────────┬──────────┐
        │   ▼            ▼            ▼          ▼          ▼
        │ GATHER       CRAFT       EXPLORE     SELL       REST/SLEEP
        │   │            │            │          │          │
        └───┴────────────┴────────────┴──────────┘          │
             完成 → 结算 → IDLE                              │
             精力 <10 → REST（中断，产出按已用时长比例）────────┘

叠加层（不改变主状态）：
  TALK    气泡挂在当前动画上，3–5 秒消失
  DRAG    拖动中，松手 → 回原状态
  HIDE    全屏应用前台，淡出；退出 3 秒后淡入
```

**计划器优先级**（服务器每 5 分钟评估一次，这是"自治"的心脏）：

| 序 | 条件 | 动作 |
|---|---|---|
| 1 | `energy < 15` | 强制睡 90 分钟（不管几点） |
| 2 | 23:00–07:00 | 睡到 07:00 |
| 3 | `energy < 40` | 休息 15–45 分钟 |
| 4 | 今日探索未做 且 `energy ≥ 60` | 探索 60–120 分钟 |
| 5 | 成品 ≥ 3 | 摆摊 60 分钟 |
| 6 | 素材够一张图纸 | 制作 40–90 分钟 |
| 7 | 素材不足 | 采集 25–40 分钟 |
| 8 | 其他 | IDLE（发呆/闲逛/说话） |

玩家改「偏好」只改第 4–7 条的权重（例如选"赚钱"就把摆摊提到第 4），**不改变规则本身**。这样"定策略"有实感，但不会退化成点击游戏。

### 2.4 活动与产出

| 活动 | 时长 | 精力/h | 饱食/h | 产出 | 触发 |
|---|---|---|---|---|---|
| 采集 gather | 25–40 min | −8 | −1.2 | 素材 2 + ⌊tier/2⌋ 个；稀有 5%+ | 素材不足 |
| 制作 craft | 40–90 min | −6 | −1.2 | 成品 ×1，耗素材 3 | 有图纸 + 素材够 |
| 探索 explore | 60–120 min | −10 | −1.5 | 事件卡 + 情报 + 稀有素材 12% | 每天 1 次（06:00 重置） |
| 摆摊 sell | 60 min | −6 | −1.2 | 金币 = 3 × 成品价（见 2.2 品质档） | 成品 ≥ 3 |
| 休息 rest | 15–45 min | +12 | −1.2 | 心情 +3/h | 精力 < 40 |
| 玩耍 play | 10–20 min | 0 | −2 | 心情 +10 | 心情 < 40 或玩家点 |
| 睡觉 sleep | 23:00–07:00 | +20 | −0.4 | — | 时段 / 强制 |

**经济自洽校验**（防止重犯"打工养不活自己"的错）：

| 项 | 数值 |
|---|---|
| 一次采集收益 | 素材 2–3 个（tier 0） |
| 一件成品成本 | 素材 3 |
| 一件成品售价 | 30 / 48 / 66 / 84 金币（tier 0–3） |
| 一次摆摊（3 件） | ≈ 90–250 金币 |
| 一顿饭（商城食物） | 8 金币，+30 饱食 |
| 一天开销 | 饱食 1.2×24 = 28.8 点 ≈ 1 顿 ≈ **8 金币** |
| 一天收入（有效工作 6–8 小时） | 采集 11–15 次 → 27–37 素材 → 9–12 件成品 → **400–500 金币** |

**结论：赚的是开销的 50 倍以上。** 金币不是生存压力，是"买图纸/买工具/买装饰"的购买力。这是刻意的——**经济不该是鞭子**。

### 2.5 桌宠行为表

| 行为 | 触发 | 时长 | 表现 |
|---|---|---|---|
| 站立 | 默认 | 20–60 s | `sin(t)` 呼吸浮动 2 px |
| 走动 | 待机后 1/3 概率 | 2–5 s，8 px / 12 fps | 左右走，碰边停，优先朝空间大的一侧 |
| 探头 | 距屏幕边 ≤ 36 px | 持续 | 半个身子出屏，只露眼睛 |
| 躺下 | 待机后 10% | 20–60 s | 躺姿，任意操作可打断 |
| 工作 | 计划中 | 25–120 min | 工具动画 + 进度气泡（每 10% 换一句文案） |
| 睡觉 | 夜间 / 强制 | 至 07:00 | Zzz，整体降亮度 20% |
| 说话 | 事件 / 定时 | 3–5 s | 气泡 + 1 个按钮，点掉即消失 |
| 被拖 | 按住 | — | 抓取姿态，松手 200 ms 落地缓冲 |
| 躲藏 | 全屏应用前台 | — | 淡出 300 ms，退出 3 s 后淡入 |

**桌面细节（Windows 4090 验收重点）**

| 项 | 规格 |
|---|---|
| 窗口 | 256×256 逻辑像素，透明、无边框、置顶、不进任务栏 |
| 点击穿透 | 透明像素必须让鼠标穿过去。WP_EX_LAYERED 逐像素 alpha 通常天然穿透，**M1 第一天验证**；不行就改"窗口跟随角色包围盒"（窗口只有 200×200，随角色移动） |
| 多显示器 | 拖动跨屏，记住位置；显示器断开回主屏 |
| 开机自启 | 注册表 Run 项 |
| 全屏检测 | 前台窗口矩形 == 屏幕尺寸 且无标题栏 → 隐藏 |
| 性能 | 空闲 CPU < 1%，内存 < 150 MB（4090 上不成问题，但要守住，防止 Godot 空转） |

### 2.6 手机端（PWA）

**5 个屏**

| 屏 | 内容 |
|---|---|
| 状态 | 角色立绘 + 4 条数值 + 当前活动 + 进度 + 3 个动作（喂 / 玩 / 摸） |
| 日报 | 今日事件流（时间 + 图标 + 一句话 + 产出），可翻历史 |
| 聊天 | 气泡 + 输入框（AI 或模板） |
| 仓库 | 素材 / 成品 / 图纸；成品可"摆到桌面"（同步到 PC） |
| 设置 | 服务器地址、免打扰、睡眠时段、AI key |

**明确不做**：悬浮窗（`SYSTEM_ALERT_WINDOW` + 前台服务 + 厂商保活，成本远高于收益）、推送、后台保活。打开 App 连上、看到同一只、聊两句，就够了。

### 2.7 AI 对话扩展点

**原则：AI 是台词层，不是引擎。** 三个调用点，全部只读。

| 调用点 | 输入 | 输出 | 频次 | 降级 |
|---|---|---|---|---|
| 对话 | persona + 最近 10 条 + 今日事件摘要 | ≤ 40 字 | 玩家触发 | 模板句库 |
| 日报旁白 | 结构化事件列表（JSON） | 第一人称日记 100–200 字 | 1 次/天 | 模板拼接 |
| 计划建议 | 数值 + 库存 + 3 天事件 | 一句建议 | 玩家主动问 | 不发请求 |

**persona 模板**（照抄 `ai.ts` 的结构，改内容）：

```
你是「{name}」，住在 {host} 电脑桌面上的一只{性格}。你{自述一句}。
现在的状态：精力 {e}%，饱食 {s}%，心情 {m}%，整洁 {t}%。
你正在：{活动名}（还剩 {n} 分钟）。
现在是 {月}月{日}日 {时}:{分}，{工作日/周末}。
今天已经发生：{事件1}；{事件2}；{事件3}。
说话要求：中文，1–2 句，不超过 40 字，不用 Markdown，不换行，不解释。
```

**五条硬规则**
1. LLM **只输出文本，永不写状态**。所有状态变更走 `action` 消息。
2. **数字校验**：回复里出现的数字必须在上下文中存在（`ai.ts` 的 `nums()` 思路），防止模型把"21 点"改成"720 点"。
3. **8 秒超时 → 模板**，宠物不会哑巴。
4. **复读检测**：连续重复 4 字以上或同一短语三次，丢弃重试一次，再失败就回模板。
5. **不做长期向量记忆**（v1）。记忆 = 会话内最近 10 条（内存）+ 今日事件（结构化）。长期记忆等玩法稳定后再说。

**成本**：单次 200–300 token；每天 50–100 次对话 + 1 次日报 ≈ **每天 ¥0.02**。

**未来扩展（v2，不在 MVP）**
- 桌宠作为 Agent 的显示器：接外部任务队列（`POST /agent/event`），桌面上显示"正在跑：渲染视频 3/5"，失败时它会慌张，成功时它会庆祝。这条把"会自己干活"从游戏内延伸到真实工作——但属于第 6 节的拍板事项，不在 MVP。

### 2.8 协议与存档

```json
// server → client：接入全量，之后有变化才推
{"type":"state","rev":1024,"ts":1762500000,
 "stage":"WORK",
 "activity":{"kind":"gather","started":1762499000,"ends":1762501000,"progress":0.5},
 "needs":{"energy":62.0,"satiety":55.0,"mood":78.0,"tidy":88.0},
 "skills":{"gathering":34.2,"crafting":12.0,"trading":8.5},
 "wallet":{"coin":86},
 "inventory":{"wood":7,"ore":3,"fiber":2}}

// client → server
{"type":"action","action":"feed","item":"berry"}
{"type":"action","action":"assign","task":"gather"}

// server → client：事件（同时写入日报）
{"type":"event","event":{"id":"e_00123","kind":"loot","ts":1762500100,
 "text":"挖到一块带纹路的石头","payload":{"ore":2}}}
```

- `rev` 单调递增，客户端丢弃 `rev` 小于当前值的包。**这个字段必须有**——原版是单进程不需要，我们两端必须防乱序和重连重复。
- 新客户端接入先推一次全量快照，再进增量循环。
- 事件 `kind` 枚举：`gather_done` `craft_done` `sell_done` `explore_found` `skill_up` `rare_loot` `player_feed` `player_play` `sleep` `wake`。

**SQLite**

```sql
pet(id, name, created_at, energy, satiety, mood, tidy, coin)
skill(pet_id, key, value, spec)              -- spec: 专精分支，null=未选
inventory(pet_id, item, count)
activity(id, pet_id, kind, started_at, ends_at, state)  -- 单行，state: running|done
event(id, pet_id, ts, kind, text, payload_json)
day(pet_id, date, report_text)               -- 日报缓存，避免重复调 LLM
```

离线补算：启动时 `now - last_tick` 按分钟切段，逐段跑计划器（上限 72 小时，超出按 72 小时算，防止一千年没开后卡死）。

## 3. 设计取舍（照搬 / 改造 / 砍掉）

| QQ 宠物的机制 | 判断 | 我们的做法 | 理由 |
|---|---|---|---|
| 数值衰减 | **改造** | 保留，但只影响效率乘子，不触发事件 | 数值要有变化才有"活着"的感觉；但不能变成惩罚 |
| 饥饿/清洁/心情 三项 | **照抄结构** | 三项 + 新增"精力" | 三项够用；精力是"能不能开工"的开关，缺了它自治循环没有节奏 |
| 健康/疾病/死亡 | **砍掉** | 无 | 恐惧驱动留存，与"零惩罚"直接冲突 |
| 成长值 + 等级 | **改造** | 换成 3 条技能（0–100）+ 专精 | 保留"变强"的实感，去掉无限 treadmill |
| 打工/上学/旅游 | **改造** | 合并成 采集/制作/探索/摆摊 | 保留"派出去 → 等回来 → 有产出"的节奏，去掉学历/属性门槛 |
| 离线进度 | **照抄** | 时间戳补算，上限 72 小时 | 这是"会自己干活"的技术前提 |
| 掉落老虎机 | **改造** | 稀有素材 5%–12%，不做 560 种物品 | 保留惊喜，控制内容量（MVP 只做 6 素材 / 8 成品） |
| 每日任务/签到 | **砍掉** | 无 | 用"日报"替代——日报是**陈述**，任务是**催办** |
| 图鉴/收集 | **推迟** | v2 | 内容成本高，先验证循环 |
| 小游戏/农场/钓鱼 | **砍掉** | 无 | 范围杀手 |
| 好友/串门/情侣 | **砍掉** | 无 | 单机项目，社交是另一个产品 |
| 粉钻/内购 | **砍掉** | 无 | 不货币化 |
| 逻辑层/动画层解耦 | **照抄** | 数值走独立 tick，不等动画回调 | 原版这条是对的，且是跨端一致的前提 |
| 活动槽互斥 + 已用分钟落盘 | **照抄** | `activity` 单行表 + 重启续算 | 简单、够用、可测 |
| 待机决策表 | **照抄** | 20–60 s 随机、10% 躺下、1/3 走动、边缘探头 | 这是"像活的"的最小实现 |
| 点击命中分部位 | **改造** | 先做整体点击 + 3 个反应，不做 10 点命中 | 10 点命中要美术配合，MVP 不值得 |
| AI 改写而非替换 | **照抄** | 数字校验 + 复读检测 + 超时降级 | 这是 `ai.ts` 里最值钱的三行设计 |
| 气泡 + 单按钮 | **照抄** | 同 | 最省事的"可交互感" |
| 托盘状态图标 | **照抄** | 4 种（正常/工作/睡觉/离线） | 不打扰但可见 |

### 4.3 里程碑（Windows 4090 验收）

|---|---|---|---|
| **M0 骨架** | 0.5 天 | `server/`：FastAPI + SQLite + `rules.json` + WS；`tools/sim.py` 命令行模拟器 | `sim.py --hours 72` 输出 3 天事件流；数值曲线合理；无异常状态 |
| **M1 桌面壳** | 1 天 | Godot 4.7：透明置顶窗口 + 占位角色 + 呼吸/走动/躺下 + 连 server | ①透明无白底 ②**透明区点击穿透** ③拖动后重启位置恢复 ④断线 3 秒重连 |

**合计 3.5 天；含 M5（AI）为 4 天。**

### 4.4 验收清单

1. 挂机 8 小时（或 `sim.py` 快进）：日报 ≥ 6 条事件，4 项数值在预期区间，库存增长，**零惩罚事件**
2. 断网 1 小时再连：两端一致，`rev` 单调，无重复事件
3. 拖到副屏 + 重启：位置恢复
4. 全屏游戏：3 秒内隐藏；退出 3 秒内回来
5. 删掉 AI key：对话与日报仍有输出
6. 连续 24 小时不操作：数值不崩（饱食见底也只降效率），回来有日报
7. 关 PC 一晚再开：按时间戳补算，日报含夜间睡眠，无"死亡"

## 6. 需要训练员拍板的 5 件事

### ① 「会自己干活」指游戏内，还是真替你干活？

| 选项 | 含义 | 代价 |
|---|---|---|
| A 游戏内自治 | 它采集/制作/摆摊，产出是游戏内资源 | 安全、可验收、纯单机；但"干活"是虚构的 |
| B 真干活 | 接真实任务（如 Hermes 任务队列），桌面显示"正在跑：渲染视频 3/5" | 贴合"系统在跑"的爽点；但要处理真实失败态、权限、隐私 |
| **C 推荐：A 为主 + B 当显示层** | 它有自己的活；同时能被外部事件驱动反应 | 两边都占，工作量 +0.5 天 |

**这个决定影响整个产品的骨架，请在开工前定。**

### ② 美术方向
- 像素（有 PixelLab 产线，最快出量，256×256 刚好）
- 2D 手绘（最贵，最耐看）
- 3D（可复用 UE5 资产，但透明窗口 + 3D 渲染在 Godot 里更重）

### ③ 桌面引擎
- **Godot 4.7**：体积小（~50 MB）、启动快、透明窗口要实测
- **Electron**：QQ 宠物同栈，透明窗口成熟，但内存 200 MB+、包体 100 MB+

### ④ 服务器常驻在哪 —— **已定（训练员 2026-11-07）**

**服务器常驻在溪流（Mac mini）上**：24/7 在线、存档权威、跨设备统一。桌面端与手机端都只是连它的薄视图；换机/换网段时由溪流侧维护地址与可达性。

**表现层跟随人走**：在电脑前 → 桌宠浮在桌面；离开 → 手机上打开就是同一个角色、同一份存档，接着刚才的状态继续。不是两份数据，也不是"同步"，而是同一台服务器换了个显示终端。

### ⑤ 角色是谁
名字、性别、人格（毒舌 / 忠犬 / 傲娇 / 冷淡 / 懒散但可靠）。这直接决定台词库语料和 AI persona，**换人格等于重写全部文案**，越早定越好。
