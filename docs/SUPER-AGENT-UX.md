# Super Agent 使用体验（训练员视角）

> 版本：v0.1（溪流起草，待训练员校正）
> 目的：把「用起来什么感觉」写成可以验收的标准，而不是靠感觉争论。
> 全部条目来自真实事故或真实反馈，不是设想。

## 一、一句话标准

**训练员永远知道三件事：现在有几个活在跑、每个到哪一步、有没有卡住需要他决定。**

不需要他记任务号、不需要他追进度、不需要他猜「这条到底发了没有」。

## 二、真实断点（2026-11 记录）

| 现象 | 真实案例 | 训练员的感受 |
|---|---|---|
| 日志说「已派」但没有证据 | 图片验收那单报「已投递」，实际收到的是旧图缓存 | 「你以为你发了，我也以为你发了，实际都是幻觉」 |
| 派活插进正在进行的人工对话 | 训练员和小栗帽聊天时，router 硬塞消息 | 「我和小栗帽正聊着呢，你的消息就过来了」 |
| 取消按了但没停 | `cancel_delivery: worker_control_unavailable` | 以为停了，其实还在跑 |
| 在跑的任务被墙钟掐死 | `turn inProgress` 仍判 `failed: deadline 到期` | 「它明明在干活，为什么算失败」 |
| worker 状态不可见 | `/workers` 显示 idle，实际在聊 | 不知道能不能派活 |
| 多线并行汇报 | 一次给三条线 + 三个待定项 | 「我都不知道回你哪一个了」 |
| 待办散落各处 | Trello 一套、BACKLOG 一份、口头几条 | 「事情越积越多，但没人知道有哪些」 |

## 三、七条体验原则

1. **有据可查**：任何「已派 / 已在跑 / 已完成」都要能立刻给出一条证据（task_id + state，或文件路径 + sha256）。给不出就说「还没验证」。
2. **单一入口**：问「现在有什么活」只问一句，就能拿到全部在跑的、排队的、卡住的任务清单。
3. **人工优先**：训练员正在和某个 worker 对话时，其他派活一律排队，不插播。
4. **失败要说人话**：错误信息必须包含「发生了什么 / 影响什么 / 下一步怎么办」，而不是 `turn unknown`、`worker_control_unavailable` 这种内部码。
5. **一次一件事**：汇报默认只给当前这一条线的结论 + 一个待决问题；多线并行时先给一页结构，别堆问题。
6. **进度可见**：长任务要有「现在做到第几步」，而不是只在结束时冒出来。
7. **可回溯**：任何决定、任何改动，事后能在文档里查到「谁定的、什么时候、为什么」。

## 四、可度量指标（建议）

- **派活可信度**：`已派` 声明中带证据的比例，目标 100%。
- **插播次数**：人工对话期间被外部任务打断的次数，目标 0。
- **状态准确度**：`/workers` 显示状态与真实状态一致的比例。
- **首响时间**：训练员发消息到第一句回应的时间，目标 < 30 秒。
- **任务可见率**：在跑任务中，能在单一入口查到的比例，目标 100%。

## 五、待补的界面 / 交互（初步）

1. **一屏总览**：在跑的、排队的、今天完成的各一行，点进去看详情。
2. **状态灯**：每个 worker 一个灯（空闲 / 忙人工对话 / 忙任务 / 离线），聊天期间自动变黄。
3. **证据链**：每个任务下面挂「创建 → 执行 → 产物」三段，每段带证据链接。
4. **失败卡片**：一句话原因 + 一句建议动作 + 一个「重试」按钮。
5. **看板**：接在 Wiki 工作台上（已在做，`/board`），把 BACKLOG 与 Trello 的排期合成一处。

## 六、不做什么

- 不做「让训练员学新术语」的界面：状态就叫「在跑 / 排队 / 卡住 / 完成」。
- 不做多层菜单：任何信息两步内可达。
- 不为了好看牺牲证据：宁可朴素，也要每一条都能点开看原始记录。
