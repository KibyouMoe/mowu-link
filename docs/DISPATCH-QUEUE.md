## 提问通道规格（训练员 22:37 定，四条目标）

1. worker 可以**正常向溪流提问**（不再过期、不再只能自己答）
2. 训练员在**飞书同时看到**这条提问（含题面与选项）
3. 溪流能收到并能：**选选项 / 跳过 / 用自己的话回答**（三种都给）
4. **DSH 也要做到同样四条**，不许只做 Codex
6. **所有 worker 都能提问（训练员 22:38）**：不只小栗帽——气槽、Rudolf、玉藻十字等 Codex 与 DSH 两侧的所有 worker，都应具备同一套提问能力（能问溪流、能问训练员），并共享同一套状态同步语义。多 worker 并发提问时不能串号。
5. **状态三向同步（训练员 22:37 追加）**：溪流答完之后 —— 飞书侧的卡片要立刻变成「已回答/已跳过」并显示答案来源；她客户端里的原生提问窗口要**同时关闭**；两边状态一致，不许一边答了另一边还挂着。

已确认的三个现场（都在这单里修）：
- `reason=source_task_ended`：任务一结束，它挂的提问立刻过期
- `question_recipient_mismatch`：`Only the bound originating agent/task may answer this question` —— 溪流无资格回答
- 客户端原生提问窗口**不消失**：答完之后弹窗还挂着

  `config`（是该 worker 的默认配置）/ `current`（是当前会话用的）/ `current,config`（两处都是）。
