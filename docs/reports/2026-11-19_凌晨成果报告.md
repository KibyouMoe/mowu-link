## 三、这一夜修掉的四个真缺陷

1. **`thread_unavailable`（-32600）**
   任务绑定的会话已失效，注入必然被拒；而代码只是对**同一个** thread 重试。
   → 首次拒绝即改道到可用会话，禁止重复撞同一线程。

2. **注入后 7 毫秒就去读输出**
   `probe_injected` 与 `probe_error(read_output)` 只隔 7ms，回合根本还没产出；更糟的是 `-32603/rpc_rejected` 被映射成 `native_image_rejected`，把"读早了"说成"图片被拒"，连续误导三轮排查。
   → 等 turn `finished` 再读；`-32603` 在时限内重读；错误码按真实原因分类。

3. **改道后丢上下文**
   换了新会话，模型不知道要干什么，回答「我会按原任务记录填报」→ summary 为空。
   → 注入 prompt 自带原题 + 「现在立刻执行并回答」；空泛摘要判无效并重试一次。

4. **`wait_turn/native_report_turn_timeout` 卡单**
   气槽去装铃鹿那张单自己卡住、无回执；实际铃鹿已升级并被探针验证。
   → 取消 + 打勾收口（仅真 bug 用），不手工改任务状态。
